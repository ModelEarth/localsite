Activate GitHub sign-in (shown on localhost)
The site admin registers one GitHub OAuth app, once. All site users sign in through that same app: GitHub asks each of them to authorize it, and the token it issues works only with their own account and forks. Users don't register an app of their own.
  1. Register a GitHub OAuth app with Application name [site title] CMS (GitHub's popup shows "Authorize" plus this name), your site's address as Homepage URL, and Redirect URI https://cloud.model.earth/api/cms/callback.
    • Leave off "Allow wildcard matching": the sign-in server always uses this exact URI, so GitHub sends sign-in codes only there.
    • Leave off "Enable Device Flow": it's for command-line tools and devices without a browser, where users type a code at github.com/login/device. Sign-in here uses the browser popup instead, and with Device Flow on, anyone with the app's public client ID could ask users to enter a code that appears to come from your app.
    • Checking "Expire user access tokens" will require daily logins: each token stops working after 8 hours, and users sign in again. A leaked token is then usable for only 8 hours, rather than until the user revokes the app.
  2. Add its CMS_GITHUB_CLIENT_ID and CMS_GITHUB_CLIENT_SECRET to your local env file, then run ./automation/sync-config.sh in CloudRoot (CMS sign-in steps)
  3. Check the CloudRoot secrets, then run Deploy Worker
  4. Uncomment auth_base_url and auth_endpoint in the cms: block of support/site/config.yaml
Until then, sign-in goes through Netlify's service ("Authorize Netlify CMS"). For the editors' "Sign In with Token" option, create a personal access token.

Example: edit one file on GitHub

Edit README opens Sveltia CMS with its own config, passed to CMS.init() through launchCMS({config}). It edits only edit/README.md in the ModelEarth/localsite repo and skips support/site/config.yaml (load_config_file: false). On localhost, choose "Sign In with Token" and paste a GitHub personal access token.

Edit site files


      Edit Files uses Sveltia CMS to edit the collections/files defined in support/site/config.yaml — it's a full Sveltia CMS interface, not a targeted editor for a particular div on the page. Settings are loaded from support/site/config.yaml via localsite/js/cms.js. Your edits are saved in your own fork of DesktopFolders/content, which is created the first time you sign in.
